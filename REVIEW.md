# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Late test is `minutes > 10` on whole minutes, so 09:40:01 gives `int(10.016) = 10`, which is not `> 10`, and the result is 0. R2 says strictly more than 10:00. | Shift 09:30, punch-in 09:40:01. The starter returns 0, the rule says 10. | Compare whole seconds: late only if `seconds > 600`, then `late_minutes = seconds // 60`. |
| 2 | `compute_late_minutes` | Shift start is built with `punch_in.replace(hour, minute)`, so it uses whatever zone the datetime carries (server local time, or UTC once PyMongo returns aware values) instead of IST. It also ignores the attendance date, so overnight shifts break. | A UTC instant of 04:10:01Z (09:40:01 IST) with shift 09:30 returns 0, because it measures from 09:30 UTC. Server in another time zone gives different answers for the same request. | Shift start is built from the record's attendance date at HH:MM in IST (`shift_start_at`). |
| 3 | `compute_work_hours` | Uses `round(x, 2)`, which is round-half-even on a binary float, and does not truncate to whole seconds. R4 wants half-up. | 450 seconds is 0.125 hours. The starter returns 0.12, the rule says 0.13. | Integer maths: `cents = (seconds * 200 + 3600) // 7200`, then `cents / 100`. Exact half-up. |
| 4 | `compute_overtime` | No 30 minute minimum (R3). Any positive gap counts. | Shift end 18:30, punch-out 18:45. The starter returns 15, the rule says 0. | Floor to whole minutes and count only if `>= 30`. |
| 5 | `compute_overtime` | Shift end is placed on the same date as the record even for overnight shifts, so the end is a day early. | Shift 22:00 to 06:00, punch-out 06:40 next day. Returns 1480, should be 40. | `shift_end_at` adds a day when `shift_end <= shift_start`. |
| 6 | `compute_overtime` | Subtracts an IST-aware datetime from `punch_out`. With the naive datetimes the starter itself produces, that raises `TypeError`, which is a 500. | Punch-out for any record that was stored by the starter. | All datetimes are UTC-aware everywhere (client opens with `tz_aware=True`, inputs are converted at the boundary). |
| 7 | `EmployeeIn` | No validation at all. `emp_code`, email, `shift_start`/`shift_end`, `joined_on` are bare strings and shifts can be equal. A bad shift such as `"25:99"` is accepted and later crashes the late calculation. | `POST /employees` with `shift_start: "25:99"` returns 201, then the first punch-in for that employee returns 500. | Pydantic patterns from the contract, a real date check on `joined_on`, and a check that the two shifts differ. All give 422. |
| 8 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) with no unique index. Two parallel requests both pass the check and both insert. | Fire the same `emp_code` twice at once. Two 201s, two documents. | Unique index on `emp_code`; the insert itself decides and `DuplicateKeyError` becomes 409. |
| 9 | `create_employee` | `created_at = datetime.now()` is naive local time, stored as if it were UTC. The response returns a datetime, which FastAPI turns into an ISO string. The contract says epoch milliseconds. | Response shows `"created_at": "2026-07-06T10:05:00.123456"`. | UTC time at millisecond precision, converted to epoch ms in `employee_out`. |
| 10 | `list_employees` | `skip = page * page_size` skips the first page. | `page=1` never returns the first employees. | `skip = (page - 1) * page_size`. |
| 11 | `list_employees` | `total` is `count_documents({})`, so the department filter is ignored in the count. No sort, so page order is undefined. | `GET /employees?department=Sales` with 2 Sales employees out of 5 reports `total: 5`. | Count with the same filter, sort by `emp_code`. |
| 12 | `list_employees` | `page` and `page_size` are unchecked. `page=-1` gives a negative skip, and PyMongo raises `ValueError: skip must be >= 0` (500). `page=0` is accepted although pages start at 1, and `page_size=100000` is accepted. | `GET /employees?page=-1`. | `page >= 1`, `1 <= page_size <= 100`, so bad values are 422. |
| 13 | `/health` | Always returns ok without touching MongoDB. | Stop MongoDB, `/health` still says 200. The contract says 503. | Pings the database and returns 503 on failure. |
| 14 | `punch_in` | Unknown employee: `emp` is `None`, then `emp["shift_start"]` raises `TypeError` (500). | Punch-in for `EMP9999`. Should be 404. | Explicit 404. |
| 15 | `punch_in` | Check-then-insert race, and no unique index on `(emp_code, date)`. | Parallel identical punch-ins give several 201s and duplicate records. | Unique index on `(emp_code, date)`. One insert wins, the rest get `DuplicateKeyError` and 409. No read before the insert. |
| 16 | `punch_in` | `datetime.fromtimestamp(ms / 1000)` gives naive server-local time and keeps milliseconds. The date comes from that local date, not IST, and nothing is truncated to whole seconds (R1). | Server running in UTC, punch-in at 02:00 IST on the 7th (20:30 UTC on the 6th). The record is stored under the 6th. | `from_ms` builds a UTC datetime cut to whole seconds, the date comes from the IST date (`attendance_date`). |
| 17 | `punch_in` | `if body.punched_at` treats `0` as missing. There is no range or type check, so a seconds-looking value like `1783312500` is accepted and becomes January 1970. Numeric strings and whole-number floats are also accepted. | `punched_at: 1783312500` returns 201 with date 1970-01-21. Contract says 422. | `EpochMs` type: strict integer between 1e11 and 4102444800000. Anything else is 422. |
| 18 | `punch_in` | No overnight handling for the date (R1). | Shift 22:00 to 06:00, punch-in at 03:00 belongs to the previous day's shift. | `attendance_date` moves an early overnight punch-in to the previous day. |
| 19 | `PunchInIn.status` | Any string is accepted, including `ABSENT`, `LEAVE` and nonsense. Only `PRESENT`, `WFH`, `ON_DUTY` are allowed here. | `status: "banana"` returns 201. | `Literal["PRESENT", "WFH", "ON_DUTY"]`. |
| 20 | `punch_in` response | Returns `id` (the ObjectId as a string), and `punch_in` as a datetime string. `_id` must never appear and instants must be epoch ms. | Response has an `id` field. | `record_out` builds the response from known fields only. |
| 21 | `list_attendance` | `list(db.attendance_logs.find(q))` loads every matching document into memory, sorts in Python and slices. At 100k records this is slow and memory heavy. | `GET /attendance` with no filter on the big dataset. | Sort, skip and limit happen in MongoDB, backed by indexes. `total` comes from `count_documents` (or the metadata count when there is no filter). |
| 22 | `list_attendance` | Sorts by `date` only, so rows with the same date come back in no fixed order and pages can overlap. | Two employees on the same day swap places between page requests. | Sort `date` descending, then `emp_code` ascending. |
| 23 | `list_attendance` | No validation of dates, status, `page`, `page_size`, and `date_from > date_to` is not rejected. Also leaks `id` and returns datetimes instead of epoch ms. Legacy records without `history` or `half_day` are returned without them. | `date_from=2026-07-09&date_to=2026-07-01`. `status=NOPE`. | Typed query params give 422. `record_out` fills missing legacy fields (`history: []`, `half_day: false`, 0 for minutes). |
| 24 | Setup | `MongoClient` is created without `tz_aware=True`, so every datetime read back is naive. Every comparison and every epoch conversion that touches them is a guess. | Any arithmetic between a stored time and an aware value raises `TypeError`. | `tz_aware=True`, and helper functions convert at the API boundary. |
| 25 | Setup | No indexes at all, and nothing creates them at startup. | `explain` on any list or analytics query shows `COLLSCAN`. | `ensure_indexes()` runs at startup and is safe to run again. |
| 26 | Whole file | Nothing handles database errors, so a MongoDB outage surfaces as a 500 with a stack trace. | Stop MongoDB and call any endpoint. | A handler turns `PyMongoError` into a 503. |

Also note anything you looked at and decided was **not** a defect, and why.

- **`load_dotenv()` at import.** It does not override variables that already exist, so real environment variables win over `.env`. This matches the contract.
- **Plain `def` endpoints with the synchronous PyMongo client.** FastAPI runs them in a thread pool and `MongoClient` is thread safe, so concurrent requests are fine. Using Motor would add nothing here.
- **`doc.pop("_id", None)` after `insert_one`.** `insert_one` adds `_id` to the dict you pass in, so removing it before returning is needed. The real problem was `id` in `punch_in`, covered in #20.
- **The default URI `mongodb://localhost:27017`.** It is only a fallback when `MONGO_URI` is not set, so nothing is hard-coded against the grader.
